## Findings considered and rejected

- **Live compositing of the notch area (masking the menu bar).** BoringNotch
  hides the menu bar and draws a fake notch over it. Bantay runs `KeepAlive`
  as an accessory app and intentionally keeps the real menu bar  -  adopting
  a fake-notch overlay is a large, invasive change that breaks menu bar
  managers and the existing island design. Not worth the risk; Bantay's
  transparency-through design is already the compatible one.
- **Global mouse tracking for hover** (NotchDrop's `EventMonitors`). Already
  solved with the island-scoped `onHover`; global monitors would re-introduce
  the "expands when far from the notch" bug. Rejected.
- **A full Shelf / widget ecosystem (NotchNook).** Out of scope for a first
  usability baseline; the notch stays a focused agent-status surface.
- **Electron/Tauri rewrite.** Per `DEVELOPMENT_PLAN.md` non-goals.

## Adversarial findings (from the first "try to break it" run)

The adversarial corpus in `.kilo/LogicCheck.swift` (A1–A5) started in a
deliberately RED state. Both findings it flushed out are now **RESOLVED** — the
harness is back to `ALL PASS` (881 checks, labels L1–L58; count corrected
2026-08-06 — earlier docs said 194 / 990):

- **F1 — RESOLVED. Resurrected pane now re-appears silently.** A pane that
  vanishes from the roster and then re-enters with the same kind no longer
  emits a *dinging* `progress` event. The `lastSeenKinds` purge was removed so
  the same-kind re-entry is a no-op; the harness asserts the re-entry never
  escalates to `accessRequest` and that any event it does produce is silent
  (`playSound == false`).
- **F2 — RESOLVED. Window is clamped to the display.** `IslandMetrics.windowFrame`
  now shrinks the fixed 504×560 frame to `min(size, screenFrame)` before
  centering, so the island stays fully on-screen on any display size while
  keeping centering + backing-grid alignment (probe at 400×300 → minX=0, minY=0).
